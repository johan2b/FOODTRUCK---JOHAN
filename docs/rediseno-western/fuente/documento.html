3. Puesta en marcha del entorno de desarrollo

3.1 Problema: «no se ve la página» en localhost:3000

Diagnóstico paso a paso:

  1. Lectura de package.json, vite.config.js y Readme.md: npm run dev lanza scripts/dev.mjs, que arranca dos procesos: Vite en 5173 (assets) y PHP en 3000 (páginas).
  2. Comprobación de puertos con ss -ltnp: nada escuchando en 3000.
  3. Comprobación de dependencias: no existían node_modules/ ni vendor/.
  4. which php: PHP no estaba instalado (causa principal). Composer tampoco.

Solución aplicada: npm ci (instala las dependencias exactas de package-lock.json, solo afecta a la carpeta del proyecto). PHP requiere sudo, por lo que se indicaron los comandos al usuario:

sudo apt update
sudo apt install php-cli php-mbstring php-xml php-curl unzip composer

Causa: composer install se ejecutó en la carpeta personal, no en la raíz del proyecto (donde está composer.json). Solución: ejecutarlo desde la raíz; se hizo y se instalaron 7 paquetes (vendor/). PHP 8.3.6 quedó verificado.

4. Método común de los componentes ilustrados

Todas las ilustraciones (hamburguesas, food truck, desierto, hoguera, grupo) se construyeron con la misma técnica: HTML + SCSS puros, sin imágenes ni JavaScript.

4.1 El lienzo y el mixin capa

Cada diseño se midió sobre su imagen de referencia (por ejemplo, 300 × 250 px para la hamburguesa) y cada ingrediente se convirtió en un elemento absoluto cuya posición se expresa en porcentajes del lienzo. Así el dibujo escala con el ancho del contenedor. El mixin evita calcular porcentajes a mano:

@use "sass:math";
$lienzoAncho: 300;
$lienzoAlto: 250;

// Coloca una capa a partir de sus coordenadas en el lienzo (x1, y1) - (x2, y2).
@mixin capa($x1, $y1, $x2, $y2) {
    left: math.percentage(math.div($x1, $lienzoAncho));
    top: math.percentage(math.div($y1, $lienzoAlto));
    width: math.percentage(math.div($x2 - $x1, $lienzoAncho));
    height: math.percentage(math.div($y2 - $y1, $lienzoAlto));
}

.moduloBurger01__tomate { @include capa(64, 196, 236, 208); }

El contenedor del dibujo tiene position: relative y aspect-ratio: 300 / 250; sus hijos, position: absolute.

4.3 Accesibilidad

Cada dibujo es un div con role="img" y un aria-label que describe lo que muestra (los span internos son presentacionales). Si un dibujo es pura decoración en una página, se recomienda aria-hidden="true".

17.3 moduloAnimar01: aparición al hacer scroll

Cómo funciona:

  1. La entrada de cada vista llama a moduloAnimar01({ selector }) con los elementos que deben aparecer (por defecto, [data-animar]).

    translate: 0 2rem;
    transition:
        opacity 700ms ease var(--animar-retraso, 0ms),
        translate 700ms cubic-bezier(0.2, 0.7, 0.2, 1) var(--animar-retraso, 0ms);

}

17.7 Flujo del pedido para llevar

  1. «Hacer pedido para llevar» enlaza a /es/contacto?pedido=llevar#contacto-telegrama-es (eu: /eu/contacto…).
  2. En contacto, moduloCarrito01 detecta ?pedido=llevar y un carrito con líneas: marca el motivo llevar, muestra el resumen, escribe un mensaje inicial si está vacío y rellena el campo oculto pedido con [{"id":"forajido","cantidad":2}, …] (sin precios).
  3. El usuario completa sus datos, el consentimiento y la operación, y envía. _artForm02.js no cambia su comportamiento.
  4. artForm02.php valida el pedido: lista de 1 a 10 líneas, cada id debe existir en carta.php y cada cantidad entre 1 y 20. Calcula subtotales y total en céntimos y los añade al mensaje del correo y de la BBDD.
  5. Al enviarse bien, _artForm02.js emite artForm02:enviado (única línea añadida a ese archivo) y el carrito se vacía.
